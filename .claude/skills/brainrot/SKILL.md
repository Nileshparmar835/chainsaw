# Direct a short from one topic

The brief is **$ARGUMENTS**. If invoked automatically, use the topic from the user's latest request. Make the creative decisions and execute the production in this session. Use the local setup, graphics, voice, score and encoder. Default to English, original characters, male narrator am_michael, portrait 1080×1920, 30 fps and roughly 30–45 seconds. Let a tight joke finish earlier or a longer requested episode breathe. Explicit creative preferences take priority.

1. Work at the project root containing CLAUDE.md and setup_studio.py. If the project Python and model files are ready, use them. Otherwise run `python setup_studio.py` using Python 3.11 or 3.12 (`py -3.12 setup_studio.py` on Windows or `python3.12 setup_studio.py` on Unix). This installs free packages into .venv and verifies voice and encoder. Use the resulting `.venv/Scripts/python.exe` on Windows or `.venv/bin/python` on macOS/Linux; activating the environment is optional.
2. Pick a new `episodes/<short-slug>/` directory. For revisions, keep earlier outputs in their own directories. Use all three project specialists for a complete video. Invoke them as skills where supported or read their SKILL.md files under .claude/skills/ directly. Apply brainrot-story first, then brainrot-voice for the performance and brainrot-animation for the artwork. Choose their *methods* from the premise, rather than repeating a stock story. The project works with this bundled set alone.
3. Select optional skills by demonstrated need. An anatomy story benefits from a body-cutaway specialist; a trick or wish benefits from a fable specialist; a recurring cast can benefit from a continuity specialist. Use only an actually available, compatible skill. Record the selected method, the key problem it solves and the skills used in the episode's direction notes. If no installed specialist covers a one-off effect, implement it directly in art.py. If the project needs the same unfamiliar capability across episodes, author a narrow project-local .claude/skills/<name>/SKILL.md (name + description frontmatter, trigger, inputs, steps, acceptance and a worked example), test it on one beat, then apply it and continue. Keep credentials and paid services out of the skill.
4. Produce `episode.json` and original `art.py` for this topic. Read studio/FORMAT.md and examples/last-pizza/episode.json for exact fields. Include every shot's environment, visible cast, props, foreground/background, camera, main action, expression, spoken performance, sound hit and handoff. The generated storyboard.md is the user's readable script and shot list. Commit to concrete acting a viewer can see. A duplicate of the example with replaced dialogue is an unfinished episode.
5. Render the draft: `<project-python> studio/render.py episodes/<slug> --draft`. Inspect draft/final.mp4, draft/contact-sheet.jpg and timeline.json. Confirm hook/reveal framing, shot changes, the instant each named object appears, visible contact, mouth/reaction timing, readable captions and continuous speaker identity. Inspect frames around tricky contacts and the final-to-first cut. When playback or listening is available, use it at normal speed. Repair the affected cues and rerender. No creative approval checkpoint.
6. Run `<project-python> studio/render.py episodes/<slug>`. The final is output/final.mp4. The encoder decodes the candidate and checks resolution, timing, picture change and audible tracks before promoting it. Inspect the final contact sheet and check the actual output file. Report what you saw or heard and any limitation accurately. Technical measurements alone do not establish comic timing.
7. Deliver the final MP4 first. Link the storyboard, caption file and editable episode directory. Include duration, format and any meaningful quality limitation. If the sandbox requests a permission only the user can grant, preserve the work and state the specific blocker. Do not bypass permissions or publish externally.

For a setup error, inspect the exit message, retry a transient download and use a compatible local Python. Models are included, with hash-checked recovery downloads. Use the imageio-ffmpeg binary when system FFmpeg is missing. Use an available free local replacement if a dependency is genuinely unavailable and document the actual replacement. Never substitute a silent movie for a narrated deliverable.
